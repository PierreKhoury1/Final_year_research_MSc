# slotbench: design contract

Research question: can a GPU finish one 5G uplink slot's signal processing inside its deadline
every time while another workload shares the GPU? Which isolation mechanism gets misses to
zero most cheaply, and does a consumer GPU (RTX 3060) behave like a datacenter one (A100/H100)?

This file is the contract every component follows. Component READMEs may add detail but must not
contradict it. All paths below are relative to `slotbench/`.

## 2. The slot workload (one 5G NR uplink slot, PUSCH-like)

Defaults model a 100 MHz carrier at 30 kHz SCS (273 PRB = 3276 subcarriers), 4 receive antennas,
4 layers, 14 OFDM symbols of which 2 carry DMRS pilots (symbols 2 and 11), 256-QAM.
Every size is a CLI flag so the graph can be tuned to about 200 us idle on the card under test.
First RTX 3060 runs (2026-09-30): rate-1/3 decoding (46 rows, 20 iterations, 50 codewords) took 5.4 ms per
slot, far over budget, so the defaults moved to the high code rate a 256-QAM slot actually uses.

| Stage | Implementation | Default size |
|---|---|---|
| S0 stamp start | 1-thread kernel: writes %globaltimer and seq to mapped pinned memory | 1 |
| S1 OFDM FFT | cufftExecC2C, batched | 14 sym x 4 ant x 4096 pt |
| S2 pilot gather | kernel: take the 3276 used bins (centred in the FFT), pack per-subcarrier Yp (4x4: antennas x {DMRS symbols 2 and 11 of subcarrier k and of k^1}) and Yd (4 x 12 data symbols), column-major | 3276 |
| S3 channel estimate | cublasCgemmStridedBatched H = Yp * Xp^H / 4, Xp a fixed orthogonal 4x4 pilot matrix | batch 3276 |
| S4 Gram + noise | cublasCgemmStridedBatched G = H^H H, then kernel adds sigma^2 I | batch 3276 |
| S5 matched filter | cublasCgemmStridedBatched R = H^H Yd (4x4 * 4x12) | batch 3276 |
| S6 LU | cublasCgetrfBatched on G (pointer arrays built once at init) | batch 3276 |
| S7 solve | cublasCgetrsBatched G X = R | batch 3276, nrhs 12 |
| S8 demod | kernel: max-log LLRs for Gray square QAM | 3276 x 12 x 4 symbols, 8 LLR each |
| S9 rate de-match | kernel: copy LLRs into per-codeword buffers (wrap modulo LLR count), zero the 2Z punctured bits | ldpc_cb codewords |
| S10 LDPC decode | layered normalized min-sum (alpha 0.75), fixed iterations, no early termination | BG1, Z 384, 8 rows (rate 0.79, typical for 256-QAM), 10 iters, codewords auto-filled (117 at 100 MHz) |
| S11 hard decision | kernel: sign -> packed bits of the 22Z systematic part | all codewords |
| S12 stamp end | 1-thread kernel: writes %globaltimer and seq, then __threadfence_system() | 1 |

LDPC decoder contract: one thread block per codeword, blockDim = Z threads; each layer is one base
row; thread z owns check node (row, z) and for each edge (col, shift) touches variable node
col*Z + (z + shift) % Z (Sionna/38.212 lifting convention: row r*Z+i connects to column c*Z+(i+s)%Z,
s = V mod Z). A posteriori LLRs live in dynamic shared memory as fp32 if they fit
(68*Z*4 bytes <= max opt-in shared memory of the device), else fp16 storage with fp32 arithmetic.
Check-to-variable messages live in global memory laid out [edge][z] (coalesced). Rows used
`ldpc_rows` in [4, 46] (fewer rows = higher code rate); columns used = 22 + ldpc_rows.
Fixed iteration count, no early stop: slot runtime must not depend on the received data.

The input data does not need to decode (it is synthetic); `--selftest` checks the GPU decoder
separately on real noisy codewords from the host encoder and must report bit errors per codeword.

Graph mode captures S0..S12 once on the slot stream (cudaStreamBeginCapture, global mode) and
replays it with cudaGraphLaunch. Streams mode (mechanism M4) enqueues the same calls one by one
every slot. cuBLAS must use cublasSetWorkspace with a preallocated buffer and cublasSetStream to the
slot stream before capture; cuFFT must use cufftSetStream. No allocation after init. Graphs are
instantiated without cudaGraphInstantiateFlagUseNodePriority so kernels inherit the launch stream's
priority.

## 3. Slot driver

`bin/slot_driver [flags]`, all flags `--name value`:

| Flag | Default | Meaning |
|---|---|---|
| --out DIR | required | output directory (created) |
| --slots N | 1000000 | recorded slots |
| --warmup N | 2000 | slots run before recording starts (not recorded) |
| --period-us F | 500 | slot period |
| --deadline-us F | 500 | miss threshold on t1 - t0 |
| --prio high/default/low | high | slot stream priority (cudaDeviceGetStreamPriorityRange) |
| --mode graph/streams | graph | M4 switch |
| --wait event/flag | event | event: cudaEventRecord after launch, spin on cudaEventQuery; flag: spin on the mapped end-stamp seq |
| --core N | -1 | pin driver thread (-1 = no pinning) |
| --collector-core N | -1 | pin collector thread |
| --fifo P | 0 | SCHED_FIFO priority for driver thread (0 = leave normal); failure is logged, not fatal |
| --spin-us F | 50 | clock_nanosleep(ABSTIME) until boundary - spin, then busy-wait to the boundary |
| --gpu N | 0 | device |
| --calib-samples N | 20000 | clock calibration brackets before and after the run |
| --label S | "" | free text copied to meta.json |
| sizes | section 2 | --fft 4096 --symbols 14 --antennas 4 --layers 4 --subcarriers 3276 --qam 256 --ldpc-cb 0 (auto) --ldpc-iters 10 --ldpc-rows 8 --ldpc-z 384 |
| --selftest | off | run GPU decoder check (and one pipeline run) then exit 0/1 |
| --tune-us F | off | measure idle graph time; try carrier widths 273/217/162/106/51 PRB (100/80/60/40/20 MHz) with codewords auto-filled, then fewer iterations at 51 PRB; print the flags (`--subcarriers N --ldpc-cb 0 --ldpc-iters M`) of the largest workload whose median idle time <= F, exit |
| --print-config | off | print resolved config JSON, exit (no GPU needed) |

Process: cudaSetDeviceFlags(cudaDeviceScheduleSpin | cudaDeviceMapHost), build pipeline, lock
memory (mlockall, failure logged), pre-calibration, warm-up, recorded loop, post-calibration,
write files. Loop per slot k: t_sched = t_start + k*period; sleep until t_sched - spin; t_wake;
spin to t_sched; t0; launch; t_launched; wait; t1; read GPU stamps; push SlotRecord to ring.
Overrun policy: if t1 is past the next boundary the driver skips to the first boundary after t1
(so slot indices have gaps; analysis counts skipped boundaries as missed). SIGINT/SIGTERM stop
the loop cleanly and still write meta.json.

Collector: a separate thread draining the SPSC ring (capacity 65536 records) into `slots.bin`
with buffered fwrite. The driver never blocks on the ring; a full ring increments
`ring_overflows`, and any overflow makes the run invalid.

Outputs in --out:
- `slots.bin`: header then records (section 4)
- `meta.json`: config, GPU name/uuid/SM count/CC/clocks, driver + CUDA versions, host name, kernel
  release, cmdline, isolated cpus (/sys/devices/system/cpu/isolated), stream priority range and
  value used, graph node count, counts (recorded, skipped boundaries, stamp mismatches,
  ring_overflows), fifo_ok, mlock_ok, clock fits pre/post (section 6), idle warm-up median,
  start/end wall time (ISO 8601 UTC), exit reason
- `calib_pre.csv`, `calib_post.csv`: t0_ns,t1_ns,gpu_ns bracket samples

## 4. Binary record format (little endian)

```
struct SlotFileHeader {       // 64 bytes
  char     magic[8];          // "SLOTBEN1"
  uint32_t version;           // 1
  uint32_t record_size;       // 64
  uint64_t n_records;         // written at clean close; 0 if the run crashed (reader uses file size)
  double   period_ns;
  double   deadline_ns;
  int64_t  t_start_ns;        // host ns of slot boundary 0
  uint8_t  reserved[16];
};
struct SlotRecord {           // 64 bytes, all times host CLOCK_MONOTONIC_RAW ns unless noted
  uint64_t slot;              // boundary index k
  int64_t  t_sched;           // scheduled boundary
  int64_t  t_wake;            // return from clock_nanosleep
  int64_t  t0;                // just before the launch call
  int64_t  t_launched;        // launch call returned
  int64_t  t1;                // completion observed
  uint64_t g0;                // GPU %globaltimer ns at S0 (0 if stamp missing)
  uint64_t g1;                // GPU %globaltimer ns at S12 (0 if stamp missing)
};
```
numpy dtype: `[("slot","<u8"),("t_sched","<i8"),("t_wake","<i8"),("t0","<i8"),("t_launched","<i8"),("t1","<i8"),("g0","<u8"),("g1","<u8")]`.

Derived metrics (analysis owns these definitions):
- latency = t1 - t0 (primary; miss if > deadline)
- latency_from_boundary = t1 - t_sched
- wake_overshoot = t_wake - (t_sched - spin_ns)
- start_lateness = t0 - t_sched
- launch_cost = t_launched - t0
- gpu_exec = g1 - g0
- queue_delay = host_of(g0) - t0 using the clock fit (section 6)
- skipped boundaries = gaps in `slot`; each counts as a miss

## 5. Adversary

`bin/adversary --workload W --duty D [flags]`, runs in its own process (MPS needs separate processes).

| Flag | Default | Meaning |
|---|---|---|
| --workload sgemm/llm/vision/idle | sgemm | W1 / W2 / W3 proxies, idle = allocate context only |
| --duty D | 100 | percent of each period spent issuing work (0 = idle) |
| --period-ms F | 100 | duty-cycle period |
| --seconds F | 0 | run time, 0 = until SIGINT/SIGTERM |
| --prio high/default/low | default | adversary stream priority |
| --gpu N | 0 | device |
| --out FILE | adversary.json | summary written at exit |
| --timeline FILE | "" | optional per-second CSV: t_s,units,units_per_s |
| --size N | 4096 | sgemm M=N=K |

Workloads: W1 `sgemm`: cublasSgemm N^3 back to back (long kernels, worst preemption case).
W2 `llm`: token-generation proxy: fp16 GEMV chain (cublasGemmEx, n=1) over layer weights totalling
about 2 GB (1B parameters fp16; flag --llm-params 1e9), memory-bound, many medium kernels;
unit = token. W3 `vision`: YOLOv8n-like proxy: per frame about 60 small kernels (conv-as-GEMM
shapes 640x640 downsampling pyramid, batch 1) plus elementwise activations; unit = frame.
Duty cycle: within each period, issue work until D% of the period has elapsed (checking after each
unit, synchronising the stream), then sleep to the period end. Units completed while active are
counted. Summary JSON: workload, duty, period_ms, prio, seconds_total, seconds_active, units,
units_per_s, tflops (W1), gb_per_s (W2), fps (W3), gpu name, pid, start/end time.
`adversary/real/dutycycle.py -- CMD...` runs any external program and duty-cycles it with
SIGSTOP/SIGCONT; llama.cpp and YOLO wrappers use it and are optional.

## 6. Clocks

Bracket sample: host t0 (monoraw ns), GPU writes %globaltimer to mapped pinned memory, host t1.
Two methods: `launch` (launch a 1-thread stamp kernel, spin until the value appears; about 5-20 us
brackets) and `pingpong` (a resident 1-thread kernel answers host sequence writes over mapped
memory, as in gpu_run/lockstep.cu; about 1-2 us brackets). Fit (common/clock_fit.h): keep the
tightest brackets (bottom 1% by width, at least 50 samples), least squares
host_mid = a * (g - g_ref) + b; report a (as ppm deviation from 1.0), b, residual rms and max
over the kept samples, min/median bracket width, and the bound
eps = half the median kept width + worst bracket violation.

`bin/clockcal --out DIR --duration-s 21600 --interval-s 60 --samples 10000 --method pingpong
--core N` writes `clock_windows.csv` (one row per window: t_host_ns, n, n_kept, offset_ns at window
centre relative to first window, rate_ppm, residual_rms_ns, residual_max_ns, min_width_ns,
median_width_ns, eps_ns, gpu_temp_c, sm_clock_mhz) plus `meta.json`. GPU temperature and SM clock
are read through NVML loaded at runtime with dlopen("libnvidia-ml.so.1") (never by spawning
nvidia-smi); if NVML is missing the two columns stay empty.

`bin/phc_offset --dev /dev/ptp0 --interval-ms 1000 --count N --out phc.csv` uses
ioctl(PTP_SYS_OFFSET_PRECISE) (fallback PTP_SYS_OFFSET_EXTENDED, keeping the narrowest of 25
sandwiches) and writes host_monoraw_ns,host_realtime_ns,phc_ns,method,width_ns.

## 7. Mechanisms and the run matrix

| Id | Name | How |
|---|---|---|
| M0 | none | driver --prio default, adversary --prio default |
| M1 | stream priority | driver --prio high, adversary --prio low |
| M2 | MPS | MPS daemon on, adversary env CUDA_MPS_ACTIVE_THREAD_PERCENTAGE=50, driver --prio high |
| M3 | time-slice | `nvidia-smi compute-policy --set-timeslice=1` (short), driver --prio high; "not supported" is recorded as a finding |
| M4 | streams not graph | M1 with driver --mode streams |
| M5 | boost clocks | M1 with clocks unlocked (`nvidia-smi -rgc -rmc`) |
| M6 | MIG | A100/H100 only: driver and adversary on separate MIG instances |

Adversaries W1 sgemm, W2 llm, W3 vision; duty D in {0, 25, 50, 75, 100}.
Config TOML (configs/*.toml):

```toml
[run]
slots = 1000000
warmup_s = 300          # adversary warm-up before the driver starts, per run procedure
settle_s = 30
repeats = 1
out_root = "runs"
driver_core = 4

fifo = 99

sizes = "--subcarriers 1272 --ldpc-cb 0 --ldpc-iters 10"   # extra driver flags from --tune-us

[matrix]
mechanisms = ["M0","M1","M2","M3","M4","M5"]
workloads = ["sgemm","llm","vision"]

```

Run directory: `runs/<config>/<M>_<W>_d<D>_r<rep>/` containing driver outputs, `adversary.json`,
`telemetry.csv` (nvidia-smi every 1 s: timestamp, temperature, sm and mem clocks, power,
utilisation, throttle reasons), `env.txt`, `run.json` (mechanism, workload, duty, rep, commands,
settings actually applied, anything not supported), `status` (ok/invalid:<reason>).
`run_matrix.py` is resumable (skips cells whose status is ok), writes `matrix.log`.

## 8. Analysis outputs

- per run: p50, p90, p99, p99.9, p99.99, max of latency (us); miss rate with 95% Clopper-Pearson
  interval (0 misses in 1e6 still gives an upper bound); jitter = p99.99 - p50; skipped
  boundaries; wake overshoot p99/max; adversary units_per_s; relative adversary throughput vs its
  solo run (D=100, no driver) when present
- figures: CCDF per mechanism (log x, log y, deadline line at 500 us); heatmap mechanism x duty
  -> miss rate per workload; Pareto adversary throughput vs miss rate; latency time series of the
  worst run; clock offset/drift over time (clock_report.py)
- validation (validate.py): D=0 run must have 0 misses and p99.99 < 300 us, ring_overflows == 0,
  stamp mismatches == 0, no thermal/power throttling in telemetry, recorded == requested slots;
  three repeats of one cell on different days -> coefficient of variation of p99.99
- `summarize.py RUN_DIR` makes `summary.json`: the stats above plus a log-binned latency
  histogram (edges 1 us .. 1 s, 100 bins per decade, counts) and the 200 worst records. The
  histogram is enough to redraw the CCDF, so cloud runs can ship summaries through logs while the
  raw slots.bin stays on the instance.

## 9. Cloud (vast.ai)

`cloud/vast.py` (stdlib only, API key from env VAST_API_KEY, never printed or written to disk)
subcommands: `offers`, `launch`, `status`, `logs`, `collect`, `destroy`, `run` (launch + wait +
collect + destroy in try/finally, hard time and cost caps). The instance runs `cloud/onstart.sh`:
install build deps, `git clone` this public repository at the requested branch, `make`,
`slot_driver --selftest`, `--tune-us`, then the requested config, then prints each run's
`summary.json` tar.gz as base64 between `=====SLOTBENCH-BEGIN <name>=====` and
`=====SLOTBENCH-END <name>=====` lines, and finally `=====SLOTBENCH-DONE=====`.
Containers cannot use isolcpus, PREEMPT_RT, SCHED_FIFO or clock locking reliably; every step
records whether it was applied, and that noise is itself a result.
